# Reklama Master — сканер тендеров

Бот просматривает закупочные площадки Узбекистана и присылает в Telegram лоты
по наружной рекламе и печати (баннер, оракал, объёмные буквы, UV-печать).

## Что проверяется сейчас
- etender.uzex.uz — тендеры и отборы
- xarid.uzex.uz — аукцион на понижение
- xarid.uzex.uz — отбор наилучших предложений (69-ПКМ)
- xt-xarid.uz — аукционы, отборы, запросы предложений, тендеры
- etender.uzex.uz — раздел отбора по 69-ПКМ
- xarid.uzex.uz — запрос предложений (Taklif so'rovi) и местный аукцион (Mahalliy auksion).
  Открываются только из Узбекистана, поэтому работают с сервера в Ташкенте.
- tendergpt.uz — коммерческие закупки частных компаний
- ebirja.uz — аукцион, местный аукцион, отбор, тендер, запрос предложений
- Milliy do'kon (xarid.uzex.uz) — торги по предложениям поставщиков. Общего списка торгов у магазина нет:
  бот находит предложения по словам `shop_keywords` и смотрит торги каждого, по 300 предложений за проверку.
  Полный круг занимает несколько часов; торг длится 48 часов. Заказчика площадка не показывает.
  Участвовать в торге может только поставщик, у которого в Milliy do'kon выставлен тот же товар.
- Elektron do'kon (xarid.uzex.uz) — такие же торги по предложениям любых поставщиков, не только местных
  производителей. Проверяется так же и отдельно: ещё 300 предложений за проверку.
- new.cooperation.uz (бывший cooperation.uz) — электронный каталог: запросы цен местным производителям.
  Проверяется только через мост (см. ниже). В открытом списке нет заказчика, региона и цены, поэтому
  такие лоты приходят с пометкой «регион не указан»; подробности — в кабинете производителя.

Категории лота бот не учитывает: он читает все открытые лоты в нужных регионах и ищет слова.
Слова в названии лота или позиций достаточно; слово только в описании считается, когда там нашлись
хотя бы две разные услуги (одно слово в длинном описании часто случайное).

Остальные разделы new.cooperation.uz (аукцион, тендер, отбор, запрос предложений) почти пустые и не проверяются.

### Мост для new.cooperation.uz
Сайт не отвечает адресам дата-центров (ни серверу бота в Ташкенте, ни зарубежным), а с обычного домашнего
или офисного интернета в Узбекистане открывается. Поэтому бот ходит на него через мост: компьютер
в Узбекистане даёт серверу свой выход в интернет только для этого сайта.

1. На компьютере должен работать вход на сервер: команда `ssh uz_vps` входит без пароля
   (ключ и запись `Host uz_vps` в файле `.ssh\config` в папке пользователя).
2. Запустить файл `tools\most.bat` из папки проекта и не закрывать его окно.
   То же самое одной командой: `ssh -N -R 1080 uz_vps`.

Пока окно открыто, бот при каждой проверке читает и new.cooperation.uz. Окно закрыли, компьютер выключили
или пропал интернет — бот эту площадку пропускает без ошибки, остальные работают как обычно.
В журнале сервера это видно по строке «Мост выключен: пропускаю cooperation_catalog».

Мост пускает к интернету компьютера только программы на самом сервере и только пока окно открыто.
Не запускайте на том же компьютере `python main.py loop --source cooperation_catalog`, пока работает мост:
это второй бот со своей базой, и лоты пришли бы дважды.

## Что бот ищет
Раздел `services` в `config.yaml` повторяет перечень услуг фирмы: у каждой услуги свой список слов.
В сообщении бот пишет, к какой услуге относится лот, а лоты из приоритетного региона
(`priority_region`, сейчас Фергана) помечает зелёным кружком.

- Правило `футболк + чоп` требует, чтобы в тексте были оба слова.
- После правки слов или регионов бот сам заново проверит открытые лоты, которые раньше не подошли.
  Уже отправленные лоты повторно не придут.

## Отдельный чат для направления
Лоты по услуге можно слать не в основной чат, а в свой. Так сделано для перевозки грузов:
в `config.yaml` раздел `service_chats` связывает услугу с настройкой `TELEGRAM_CHAT_ID_TRANSPORT`.

1. Создайте группу в Telegram, добавьте в неё бота и напишите там любое сообщение.
2. `python main.py chatid` покажет ID группы. Впишите его в `.env` как `TELEGRAM_CHAT_ID_TRANSPORT`,
   а на GitHub добавьте секрет с тем же названием.

Пока ID не задан, бот эту услугу не ищет. Когда он появится, бот сам проверит открытые лоты заново.

## Служебные сообщения
- Площадка не ответила три проверки подряд — бот пишет об этом в чат, а когда она заработает, пишет ещё раз.
- В час `daily_summary_hour` (по Ташкенту) приходит итог дня: сколько лотов просмотрено и отправлено.
  Если итог не пришёл, значит, бот не запускался.

## Настройка Telegram
1. В Telegram напишите @BotFather, команда `/newbot`, получите токен.
2. Откройте файл `.env` и впишите токен после `TELEGRAM_BOT_TOKEN=`.
3. Напишите своему новому боту `/start` (или добавьте его в группу и напишите там).
4. Выполните `python main.py chatid` — покажет ID чата. Впишите его после `TELEGRAM_CHAT_ID=`.
5. Выполните `python main.py test` — в Telegram должно прийти проверочное сообщение.

## Запуск
```
python main.py run --dry-run    пробный проход: печатает на экран, ничего не шлёт и не запоминает
python main.py run              один проход с отправкой в Telegram
python main.py loop             работать постоянно: каждые interval_minutes в часы work_hours, ночью спит
python main.py prices           цены конкурентов в Milliy do'kon
```
Слова услуг и регионы меняются в `config.yaml`.
Уже отправленные лоты хранятся в `lots.db`; если удалить файл, бот пришлёт всё заново.

## Где бот работает

С 18.11.2026 бот работает на сервере в Ташкенте, а не на GitHub. Там он запущен как служба `lot-scan`:
команда `python main.py loop` проверяет площадки каждые 20 минут с 07:00 до 20:59 по Ташкенту
(часы — `work_hours` в `config.yaml`), ночью спит. После сбоя или перезагрузки сервера служба стартует сама.

- Посмотреть, как идут проверки: `ssh uz_vps 'journalctl -u lot-scan -n 50 -o cat'`
- Обновить бота после изменений в коде: `ssh uz_vps 'cd ~/lot_scan && git pull && sudo systemctl restart lot-scan'`
- Остановить: `ssh uz_vps 'sudo systemctl stop lot-scan'`

Что уже просмотрено и отправлено, бот хранит в файле `lots.db` на сервере. Лот считается дублем и второй раз
не отправляется, если совпали название, заказчик и цена и срок прошлого лота ещё не вышел.

Расписание на GitHub (`.github/workflows/scan.yml`, «Скан лотов») выключено и должно оставаться выключенным,
пока работает сервер: вместе они прислали бы каждый лот дважды. По той же причине не запускайте
`python main.py loop` на своём компьютере без `--source` или `--dry-run`.
