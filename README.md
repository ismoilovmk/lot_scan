# Reklama Master — сканер тендеров

Бот просматривает закупочные площадки Узбекистана и присылает в Telegram лоты
по наружной рекламе и печати (баннер, оракал, объёмные буквы, UV-печать).

## Что проверяется сейчас
- etender.uzex.uz — тендеры и отборы
- xarid.uzex.uz — аукцион на понижение
- xarid.uzex.uz — отбор наилучших предложений (69-ПКМ)
- xt-xarid.uz — аукционы, отборы, запросы предложений, тендеры
- etender.uzex.uz — раздел отбора по 69-ПКМ
- tendergpt.uz — коммерческие закупки частных компаний
- ebirja.uz — аукцион, местный аукцион, отбор, тендер, запрос предложений
- new.cooperation.uz — электронный каталог: запросы цен местным производителям.
  Открывается только из Узбекистана, поэтому на GitHub выключен (см. ниже).
  В открытом списке нет заказчика, региона и цены, поэтому такие лоты приходят с пометкой
  «регион не указан»; подробности — в кабинете производителя.

Категории лота бот не учитывает: он читает все открытые лоты в нужных регионах и ищет слова
в названии, позициях и описаниях.

Пока не подключены два раздела xarid.uzex.uz: «Mahalliy auksion» и «Taklif so'rovi» (запрос предложений).
С зарубежных адресов они не открываются, из Узбекистана открываются.
Остальные разделы new.cooperation.uz (аукцион, тендер, отбор, запрос предложений) сейчас почти пустые.

### Площадки, которые открываются только из Узбекистана
Серверы GitHub стоят за рубежом, поэтому `cooperation_catalog` в `config.yaml` выключен: иначе каждая проверка
заканчивалась бы ошибкой. С компьютера в Узбекистане эту площадку можно проверять отдельно, не мешая GitHub:
```
python main.py loop --source cooperation_catalog
```
Эта команда проверяет только названную площадку, даже выключенную, поэтому лоты не приходят дважды.

## Что бот ищет
Раздел `services` в `config.yaml` повторяет перечень услуг фирмы: у каждой услуги свой список слов.
В сообщении бот пишет, к какой услуге относится лот, а лоты из приоритетного региона
(`priority_region`, сейчас Фергана) помечает зелёным кружком.

- Правило `футболк + чоп` требует, чтобы в тексте были оба слова.
- После правки слов или регионов бот сам заново проверит открытые лоты, которые раньше не подошли.
  Уже отправленные лоты повторно не придут.

## Отдельный чат для направления
Лоты по услуге можно слать не в основной чат, а в свой. Так сделано для перевозки грузов:
в `config.yaml` раздел `service_chats` связывает услугу с настройкой `TELEGRAM_CHAT_ID_TRANSPORT`.

1. Создайте группу в Telegram, добавьте в неё бота и напишите там любое сообщение.
2. `python main.py chatid` покажет ID группы. Впишите его в `.env` как `TELEGRAM_CHAT_ID_TRANSPORT`,
   а на GitHub добавьте секрет с тем же названием.

Пока ID не задан, бот эту услугу не ищет. Когда он появится, бот сам проверит открытые лоты заново.

## Служебные сообщения
- Площадка не ответила три проверки подряд — бот пишет об этом в чат, а когда она заработает, пишет ещё раз.
- В час `daily_summary_hour` (по Ташкенту) приходит итог дня: сколько лотов просмотрено и отправлено.
  Если итог не пришёл, значит, бот не запускался.

## Настройка Telegram
1. В Telegram напишите @BotFather, команда `/newbot`, получите токен.
2. Откройте файл `.env` и впишите токен после `TELEGRAM_BOT_TOKEN=`.
3. Напишите своему новому боту `/start` (или добавьте его в группу и напишите там).
4. Выполните `python main.py chatid` — покажет ID чата. Впишите его после `TELEGRAM_CHAT_ID=`.
5. Выполните `python main.py test` — в Telegram должно прийти проверочное сообщение.

## Запуск
```
python main.py run --dry-run    пробный проход: печатает на экран, ничего не шлёт и не запоминает
python main.py run              один проход с отправкой в Telegram
python main.py loop             работать постоянно: каждые interval_minutes в часы work_hours, ночью спит
python main.py prices           цены конкурентов в Milliy do'kon
```
Слова услуг и регионы меняются в `config.yaml`.
Уже отправленные лоты хранятся в `lots.db`; если удалить файл, бот пришлёт всё заново.

## Работа по расписанию на GitHub
Файл `.github/workflows/scan.yml` проверяет площадки каждые 20 минут с 07:00 до 20:59 по Ташкенту
(часы — `work_hours` в `config.yaml`).

Собственное расписание GitHub срабатывает редко — пару раз в сутки вместо 42. Поэтому каждая проверка
в конце сама назначает следующую: запускает этот же файл, тот ждёт нужное время и проверяет площадки.
Сторонние сервисы и личные токены для этого не нужны. Расписание GitHub осталось запасным: если цепочка
оборвётся, оно поднимет её при следующем срабатывании. Запустить цепочку сразу можно вручную (пункт 2 ниже).

Во вкладке Actions запуск «в работе» большую часть времени просто ждёт следующей проверки — это нормально.
Запуски со статусом «отменён» тоже нормальны: новый запуск отменяет ожидание прежнего, чтобы цепочка была одна.

1. В репозитории: Settings → Secrets and variables → Actions → New repository secret.
   Добавьте два секрета: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (значения из `.env`).
2. Вкладка Actions → «Скан лотов» → Run workflow — запуск вручную, можно с галочкой пробного прохода.

Что уже просмотрено и отправлено, бот хранит в файле `lots.db` в отдельной ветке `state`: так база не теряется
между запусками, и лоты не приходят повторно. Лот считается дублем и второй раз не отправляется, если совпали название,
заказчик и цена и срок прошлого лота ещё не вышел.

Если проход не смог проверить какую-то площадку, запуск помечается красным и GitHub присылает письмо.
Пока бот работает на GitHub, не запускайте `python main.py loop` на компьютере: базы у них разные,
и лоты придут дважды.
